# Lesson 12: LCD 1602 Driver

## Goal
Write your own driver for the 16×2 character LCD and show live data on it: uptime and a counter of blue-button presses.

## What you learn
- Driving a parallel device through an **I/O expander** (PCF8574)
- Following a datasheet initialisation sequence
- 4-bit mode: sending a byte as two nibbles
- Enable strobes and timing
- Updating a display without flicker
- Mixing 5 V and 3.3 V devices: a separate I2C bus

## How it works
The LCD itself (HD44780 controller) has a **parallel** interface: RS (command/data), RW (read/write), EN (strobe), D0–D7. The blue board on its back (the "backpack") is a **PCF8574**: an I2C chip with 8 output pins. Writing one byte over I2C sets those 8 pins. Usual wiring:

| PCF8574 bit | LCD signal |
|---|---|
| P0 | RS (0 = command, 1 = character) |
| P1 | RW (always 0 = write) |
| P2 | EN (LCD latches data on its falling edge) |
| P3 | Backlight |
| P4–P7 | D4–D7 |

Only 4 data lines are connected, so every byte is sent in **4-bit mode**: high nibble first, then low nibble, each latched by an EN pulse (HIGH then LOW).

## Parts and wiring
The LCD needs **5 V**, and its backpack's pull-ups pull SDA/SCL to 5 V. That must not reach the 3.3 V modules on I2C1, so the LCD gets **I2C3**.

| LCD backpack pin | Board pin |
|---|---|
| GND | GND |
| VCC | 5V |
| SDA | PC9 |
| SCL | PA8 |

PA8 and PC9 are 5 V tolerant (FT), so the 5 V pull-ups are safe for the board.

## CubeMX setup
1. **Connectivity → I2C3**: mode *I2C*. Make sure the pins are **PA8 (SCL)** and **PC9 (SDA)**.
2. Speed Mode *Standard*, 100000 Hz.
3. Generate.

First scan I2C3 by calling this from `App_Start()` (`#include "log.h"`). Expect **0x27** (PCF8574) or **0x3F** (PCF8574A).

```c
for (uint16_t address = 1; address < 128; address++)
{
  if (HAL_I2C_IsDeviceReady(&hi2c3, address << 1, 2, 5) == HAL_OK)
    LOG("found 0x%02X\n", address);
}
```

## Steps

### Step 1: Low-level writes

`Core/Inc/lcd.h`:

```c
#pragma once
#include <stdint.h>

void Lcd_Init(void);
void Lcd_Clear(void);
void Lcd_SetCursor(uint8_t row, uint8_t column);
void Lcd_Print(const char *text);
void Lcd_Printf(uint8_t row, const char *format, ...);
```

`Core/Src/lcd.c`:

```c
#include "lcd.h"
#include "main.h"
#include <stdarg.h>
#include <stdio.h>

extern I2C_HandleTypeDef hi2c3;

#define LCD_ADDR      (0x27 << 1)
#define LCD_RS        0x01
#define LCD_EN        0x04
#define LCD_BACKLIGHT 0x08

static void WriteNibble(uint8_t nibble, uint8_t rs)
{
  uint8_t data = (nibble << 4) | rs | LCD_BACKLIGHT;
  uint8_t sequence[2] = { data | LCD_EN, data };
  HAL_I2C_Master_Transmit(&hi2c3, LCD_ADDR, sequence, 2, 10);
}

static void WriteByte(uint8_t value, uint8_t rs)
{
  WriteNibble(value >> 4, rs);
  WriteNibble(value & 0x0F, rs);
}

static void Command(uint8_t command)
{
  WriteByte(command, 0);
}
```

`sequence` sends the nibble with EN HIGH, then the same nibble with EN LOW. The falling edge latches it. One I2C byte takes ~90 µs at 100 kHz, much longer than the LCD's minimum pulse width (450 ns), so no extra delay is needed.

### Step 2: Initialisation
From the HD44780 datasheet, *"Initializing by instruction"*, 4-bit interface. After power-up the LCD might be in 8-bit mode, or halfway through a 4-bit transfer. Sending `0x3` three times forces it into a known 8-bit state; then `0x2` switches to 4-bit.

```c
void Lcd_Init(void)
{
  HAL_Delay(50);
  WriteNibble(0x03, 0);
  HAL_Delay(5);
  WriteNibble(0x03, 0);
  HAL_Delay(1);
  WriteNibble(0x03, 0);
  HAL_Delay(1);
  WriteNibble(0x02, 0);
  HAL_Delay(1);

  Command(0x28);
  Command(0x08);
  Lcd_Clear();
  Command(0x06);
  Command(0x0C);
}

void Lcd_Clear(void)
{
  Command(0x01);
  HAL_Delay(2);
}
```

| Command | Meaning |
|---|---|
| `0x28` | function set: 4-bit, 2 lines, 5×8 font |
| `0x08` | display off |
| `0x01` | clear (slow: 1.5 ms) |
| `0x06` | entry mode: cursor moves right after each character |
| `0x0C` | display on, cursor hidden |

Delays in `Init` are fine: it runs once at start-up.

### Step 3: Text

```c
void Lcd_SetCursor(uint8_t row, uint8_t column)
{
  Command(0x80 | ((row ? 0x40 : 0x00) + column));
}

void Lcd_Print(const char *text)
{
  while (*text)
    WriteByte((uint8_t)*text++, LCD_RS);
}
```

Line 2 starts at display memory address `0x40`, not 16. That's a quirk of the controller.

Test: `Lcd_Init(); Lcd_Print("Hello, world!");`

**Blank screen or a row of white boxes?** Turn the blue **contrast potentiometer** on the backpack with a small screwdriver. This is the most common "my code doesn't work" problem with these displays.

### Step 4: Printf to a line, no flicker

```c
void Lcd_Printf(uint8_t row, const char *format, ...)
{
  char buffer[17];
  char padded[17];
  va_list args;
  va_start(args, format);
  vsnprintf(buffer, sizeof(buffer), format, args);
  va_end(args);

  snprintf(padded, sizeof(padded), "%-16s", buffer);
  Lcd_SetCursor(row, 0);
  Lcd_Print(padded);
}
```

Calling `Lcd_Clear()` every update makes the screen flicker (blank, then redraw). Instead, overwrite each line padded with spaces to 16 characters: `%-16s` left-aligns and pads. Leftover characters from a longer previous text get overwritten.

### Step 5: Live dashboard
In a `Dashboard_Update()` that runs every 200 ms (`pressCount` is incremented in `App_Update()` on the blue button's rising edge, which `app.c` already detects):

```c
Lcd_Printf(0, "Up %lus", HAL_GetTick() / 1000);
Lcd_Printf(1, "Presses %lu", pressCount);
```

Updating faster than ~5 Hz is pointless: LCD crystals are slow and fast changes look smeared.

### Step 6: Measure the cost
Writing 32 characters = 64 nibbles = 64 I2C transfers ≈ **20 ms** of blocking I2C. Time `Dashboard_Update()` with `HAL_GetTick()`. That's why you don't redraw it 100 times a second.

## Troubleshooting
| Symptom | Cause |
|---|---|
| Backlight on, nothing visible | contrast pot |
| Top row of boxes | init failed: wrong address, or init sequence timing |
| Random characters | 4-bit mode lost sync: brownout or I2C error mid-byte, so re-run init |
| Not found by scanner | PA8/PC9 swapped, 5 V missing, or I2C3 on other pins in CubeMX |
| Backlight off | `LCD_BACKLIGHT` bit missing in a write, or backlight jumper removed |

## Challenges
1. **Custom characters**: the LCD has 8 user-defined 5×8 characters. Write 8 bytes after command `0x40 + n * 8`, then print character `n`. Make a degree symbol and a 5-step progress bar.
2. Draw a horizontal bar graph across all 16 columns with your custom characters (80 steps of resolution). Drive it with uptime (a sawtooth every 10 s) or, after lesson 08, with the potentiometer.
3. Make updates non-blocking: keep a 32-char "desired" buffer and a "shown" buffer; in each `Update()` send at most one changed character.
