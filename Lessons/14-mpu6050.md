# Lesson 14: Tilt Meter (MPU6050)

## Goal
Read acceleration and rotation from the MPU6050, compute tilt angles, fuse the two sensors with a complementary filter, and show a "bubble level" on the OLED.

## What you learn
- Register-based sensors: wake up, configure, read a block
- Big-endian 16-bit signed data
- Scaling raw values to physical units
- Why an accelerometer alone is noisy and a gyroscope alone drifts
- Sensor fusion with a complementary filter
- Floats on a Cortex-M4F (it has a hardware FPU)

## Parts and wiring

| MPU6050 (GY-521) pin | Board pin |
|---|---|
| VCC | 3V |
| GND | GND |
| SCL | PB6 |
| SDA | PB9 |
| AD0, INT, XDA, XCL | not connected |

AD0 unconnected = LOW → address **0x68**. Keep the OLED connected on the same bus.

## Key registers (from the MPU-6000 register map)

| Register | Address | What |
|---|---|---|
| WHO_AM_I | 0x75 | reads 0x68 on a genuine chip |
| PWR_MGMT_1 | 0x6B | chip starts in **sleep**; write 0x01 to wake it, clocked from the gyro |
| SMPLRT_DIV | 0x19 | sample rate = 1 kHz / (1 + value) |
| CONFIG | 0x1A | digital low-pass filter |
| GYRO_CONFIG | 0x1B | 0x00 = ±250 °/s → **131** LSB per °/s |
| ACCEL_CONFIG | 0x1C | 0x00 = ±2 g → **16384** LSB per g |
| ACCEL_XOUT_H | 0x3B | start of 14 bytes: accel X/Y/Z, temperature, gyro X/Y/Z |

Each value is a **signed 16-bit, high byte first** (big-endian).

## Steps

### Step 1: Who are you?

`Core/Src/mpu6050.c`:

```c
#include "mpu6050.h"
#include "main.h"
#include "log.h"

extern I2C_HandleTypeDef hi2c1;

#define MPU_ADDR (0x68 << 1)

static void WriteRegister(uint8_t reg, uint8_t value)
{
  HAL_I2C_Mem_Write(&hi2c1, MPU_ADDR, reg, I2C_MEMADD_SIZE_8BIT, &value, 1, 10);
}

static uint8_t ReadRegister(uint8_t reg)
{
  uint8_t value = 0;
  HAL_I2C_Mem_Read(&hi2c1, MPU_ADDR, reg, I2C_MEMADD_SIZE_8BIT, &value, 1, 10);
  return value;
}

void Mpu_Init(void)
{
  LOG("WHO_AM_I = 0x%02X\n", ReadRegister(0x75));

  WriteRegister(0x6B, 0x01);
  HAL_Delay(10);
  WriteRegister(0x19, 0x04);
  WriteRegister(0x1A, 0x03);
  WriteRegister(0x1B, 0x00);
  WriteRegister(0x1C, 0x00);
}
```

Got **0x68**? Genuine. Got 0x70, 0x72 or 0x98? It's a compatible clone (MPU6500 or similar). The registers used here are the same, so continue.

`Mem_Write` / `Mem_Read` do "write register address, then write/read data" in one call, the pattern used by nearly every I2C sensor.

### Step 2: Read all axes in one burst

```c
typedef struct
{
  int16_t ax, ay, az;
  int16_t temperature;
  int16_t gx, gy, gz;
} MpuRaw;

static int16_t Be16(const uint8_t *p)
{
  return (int16_t)((p[0] << 8) | p[1]);
}

void Mpu_ReadRaw(MpuRaw *out)
{
  uint8_t b[14];
  HAL_I2C_Mem_Read(&hi2c1, MPU_ADDR, 0x3B, I2C_MEMADD_SIZE_8BIT, b, sizeof(b), 10);
  out->ax = Be16(&b[0]);
  out->ay = Be16(&b[2]);
  out->az = Be16(&b[4]);
  out->temperature = Be16(&b[6]);
  out->gx = Be16(&b[8]);
  out->gy = Be16(&b[10]);
  out->gz = Be16(&b[12]);
}
```

Why one 14-byte read instead of 7 separate ones? The chip updates all registers at once. Separate reads could mix X from one sample with Z from the next. Burst reads are atomic.

The `(int16_t)` cast matters: `0xFF38` must become -200, not 65336.

Log the raw values with the board lying flat. Expect `az ≈ 16384` (1 g pointing up) and the others near 0. Tilt it and watch gravity move between axes.

### Step 3: Physical units and angles

```
a [g]     = raw / 16384.0
ω [°/s]   = raw / 131.0
T [°C]    = raw / 340.0 + 36.53
```

Convert in a `Mpu_Read(MpuData *out)` function that fills a struct of floats: `ax, ay, az` in g, `gxDps, gyDps, gzDps` in °/s, `celsius`. Put `MpuRaw`, `MpuData` and the public functions in `mpu6050.h`.

**Accelerometer angles**: at rest, the accelerometer measures gravity, so its direction gives tilt:

```c
#include <math.h>

#define RAD_TO_DEG 57.29578f

float accRoll  = atan2f(ay, az) * RAD_TO_DEG;
float accPitch = atan2f(-ax, sqrtf(ay * ay + az * az)) * RAD_TO_DEG;
```

`atan2f` and `sqrtf` come from the maths library. If you get `undefined reference to atan2f`, add `m` to `target_link_libraries` in `CMakeLists.txt`.

Tap the table: the angles jump. The accelerometer can't tell a tap from a tilt.

**Gyroscope angles**: integrate rotation speed over time:

```c
gyroRoll += gxDps * dt;
```

Smooth, ignores taps, but **drifts**: a tiny constant error adds up forever. Watch it wander over a minute.

### Step 4: Gyro bias calibration
At rest, the gyro reads small non-zero values (bias). Measure and subtract:

```c
static float biasX, biasY, biasZ;

void Mpu_CalibrateGyro(void)
{
  MpuRaw r;
  int32_t sx = 0, sy = 0, sz = 0;
  for (int i = 0; i < 500; i++)
  {
    Mpu_ReadRaw(&r);
    sx += r.gx; sy += r.gy; sz += r.gz;
    HAL_Delay(2);
  }
  biasX = sx / 500.0f; biasY = sy / 500.0f; biasZ = sz / 500.0f;
}
```

Subtract the bias before scaling: `gxDps = (r.gx - biasX) / 131.0f`. Keep the board still for that second. Drift drops a lot but doesn't vanish.

### Step 5: Complementary filter
Trust the gyro for fast changes, and let the accelerometer slowly correct the drift:

```c
roll  = 0.98f * (roll  + gxDps * dt) + 0.02f * accRoll;
pitch = 0.98f * (pitch + gyDps * dt) + 0.02f * accPitch;
```

Run it at a **fixed rate**, e.g. every 10 ms (`dt = 0.01f`). If the loop timing varies, measure `dt` from `HAL_GetTick()` instead.

0.98 / 0.02 sets the crossover: higher = smoother but slower to correct drift. Try 0.9 and 0.995.

This is the same idea phones and drones use (they use fancier filters: Kalman, Madgwick).

### Step 6: Bubble level on the OLED

```c
int32_t bx = OLED_WIDTH / 2 + (int32_t)(roll * 1.5f);
int32_t by = OLED_HEIGHT / 2 + (int32_t)(pitch * 1.5f);
Oled_Clear();
Oled_FillRect(bx - 3, by - 3, 7, 7, 1);
Oled_FillRect(OLED_WIDTH / 2, 0, 1, OLED_HEIGHT, 1);
Oled_FillRect(0, OLED_HEIGHT / 2, OLED_WIDTH, 1, 1);
```

Plus the angles as text. Update the display at ~20 fps, and the filter at 100 Hz independently.

**Printing floats**: this project links with `nano.specs`, whose `printf` has **no `%f` support** by default. Print tenths as integers: `snprintf(text, 22, "R %ld", (int32_t)(roll * 10))`, or add `-u _printf_float` to the linker flags (costs ~10 KB flash).

## Troubleshooting
| Symptom | Cause |
|---|---|
| All zeros | chip still asleep: PWR_MGMT_1 not written |
| Values like 65000 | missing `(int16_t)` cast |
| Angles jump by 360° | that's `atan2` near ±180°: normal when upside-down |
| Gyro angle drifts fast | bias not subtracted, or wrong `dt` |
| Readings freeze | I2C error: check return values, see lesson 11 |

## Challenges
1. Use the **INT** pin: enable "data ready" interrupt (register 0x38), connect INT to a free EXTI pin, read only when new data is ready.
2. Read with `HAL_I2C_Mem_Read_DMA` so the 14-byte read doesn't block.
3. Compare with the **on-board accelerometer** (LIS302DL / LIS3DSH on SPI1, PE3 = CS). Same physics, different bus.
4. Detect **taps** and **free fall** (all three axes near 0 g) and beep the buzzer.
